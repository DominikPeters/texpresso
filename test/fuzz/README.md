# Fuzzing

libFuzzer harnesses for the parts of the frontend that consume untrusted or
racy input, built with AddressSanitizer and UndefinedBehaviorSanitizer.

```sh
make config          # once; the fuzz build reuses Makefile.config's libraries
make fuzz            # build every harness into build/fuzz
make fuzz-replay     # run seeds and saved regressions once (quick, no fuzzing)
make fuzz-run FUZZ_SECONDS=600
python3 test/fuzz/fuzz.py run editor --seconds 3600 --jobs 8
```

A clang that ships libFuzzer is required; Apple's does not. `fuzz.py` finds
Homebrew's (`brew install llvm`) automatically, or set `FUZZ_CC`/`FUZZ_CXX`.
`FUZZ_CFLAGS`/`FUZZ_LIBS` replace the flags taken from `Makefile.config`.

## Harnesses

| Harness | Input | Oracle beyond "no crash, no leak" |
|---|---|---|
| `dvi` | one DVI/XDV output, indexed and rendered | |
| `incremental` | a sequence of output edits: chunked appends, cuts inside instructions, rollbacks, same-length compiler restarts, renders | after every step the incremental index agrees with a fresh index of the same bytes (pages, destinations, rendered pixels or failure) |
| `special` | NUL-separated `\special` strings placed between drawing operations over several pages | |
| `channel` | socket writes from a worker, some carrying descriptors like CHLD, then reads, peeks and resets | every passed descriptor is returned or closed |
| `editor` | raw JSON/S-expression protocol text, or synthesized change commands with hostile numbers, split at arbitrary read boundaries | resolved spans stay inside the file; on valid UTF-8, `change-range` matches a model of LSP UTF-16 positions |

Every input runs in a fresh MuPDF context whose allocations are counted, so
leaks are findings even without LeakSanitizer (unavailable on macOS). No file
or provider hooks are installed: fonts, images and font maps never load, so
fuzzed names cannot trigger IO.

## Inputs

- `seeds/<harness>/`: starting points, regenerated by `seeds.py`.
- `regressions/<harness>/`: inputs that once crashed. Name them after the bug.
  `make fuzz-replay` runs them.
- `dicts/<harness>.dict`: libFuzzer dictionaries.
- `build/fuzz/corpus/<harness>/`: the corpus libFuzzer grows. Not committed.
- `build/fuzz/findings/<harness>/`: crashes from the last run.

To reproduce a finding: `build/fuzz/fuzz-<harness> <file>`.
